## 1. このアプリは何をするか

キーワードの一致ではなく、**文章の意味**で Zotero ライブラリを扱います。

| 画面 | できること |
|---|---|
| ダッシュボード | 登録文献数、チェック済み引用数、要確認の引用数、最近の文献とファクトチェック履歴 |
| ライブラリ | Zotero の文献とアプリに直接追加した PDF の一覧。フォルダ、文字列、タグ、お気に入りで絞り込み |
| 文献ビューア | 抽出した本文と元の PDF を切り替えて表示。AI 重要文マーカー（緑）と「探したい文」マーカー（黄）、関連文献 |
| 意味検索 | ライブラリ全体から、質問と意味の近い**一節**を類似度順に表示（日英横断） |
| 引用ファクトチェック | 原稿中の引用を原文と照合し、支持 / 一部支持 / 矛盾 / 文献なし を根拠の一文つきで判定 |
| 関連グラフ | 引用関係と内容の類似を可視化 |
| 設定 | Zotero データフォルダ、検索の件数としきい値、Embedding モデル、AI 機能 |

仕組みの核心は次の 2 つです。

- **潜在ベクトル化（埋め込み）**: 本文を文単位の「一節」に分け、一節ごとに
  埋め込みモデルで数値ベクトルに変換します。意味が近い文章はベクトルも近くなります。
- **コサイン類似度**: 質問文も同じモデルでベクトルにし、保存済みのベクトルとの
  類似度が高い順に並べます。マーカー、ファクトチェック、関連グラフも同じベクトルを使います。

すべてこの Mac の中で動作し、Zotero のデータベースには書き込みません。

```
│ LocalLibrary │  │ FAISS           │  │ 一節の本文・マーカー・お気に │
│ （読み取り）  │  │ index.faiss     │  │ 入り・フォルダ・チェック履歴 │
└──────────────┘  │ metadata.json   │  │ library.db                  │
```

- 画面と CLI は `Services` だけを呼びます。モデルや索引の組み合わせは `Services` が持ちます。
- 重い処理（同期、検索、マーカー、ファクトチェック）は `QThread` 上で実行し
  （[ui/workers.py](../src/ui/workers.py)）、画面は固まりません。
- 埋め込みモデルは複数のスレッドから使われるため、`Embedder` 内のロックで
  一度に 1 つの処理だけが使います。同期と PDF 取り込みは `Indexer` のロックで直列になります。

## 3. インデックス構築の流れ

| 段階 | 内容 | 実装 |
|---|---|---|
| 1 | Zotero に接続（ローカル API、だめなら DB の読み取り専用コピー） | [zotero_client.py](../src/zotero_client.py) |
| 2 | 文献を取得（`item_types` の種別）。アプリに追加した PDF も合流 | `ZoteroClient.fetch_papers()`, [local_library.py](../src/local_library.py) |
| 3 | 本文を一節に分割 | [chunker.py](../src/chunker.py) |
| 4 | 一節ごとに潜在ベクトル化 | [embedder.py](../src/embedder.py) |
| 5 | 一節の本文を `library.db` に、ベクトルを FAISS に保存 | [library_db.py](../src/library_db.py), [vector_store.py](../src/vector_store.py) |

### 一節への分割

- 本文を文に分け（英語と日本語の句読点）、連続する文を **256 トークン以内**
  （`chunk_tokens`）にまとめて一節にします。一節どうしは重なりません。
- 一節ごとに PDF の開始ページを記録します。検索結果やマーカーから該当ページへ移動できます。
- 参考文献リストらしい一節には印を付け、意味検索の対象から外します
  （著者名や年の羅列がヒットするのを防ぐため）。
- 本文が取れない文献はタイトルだけを索引し、一覧には表示されます。

文献 1 件は複数のベクトルを持ちます。文献単位のスコアは、その文献の一節の
類似度の最大値です（`score_aggregation = "max"`）。

## 4. データの保存先と保存タイミング

### 保存先

すべて **`~/Library/Application Support/Zotero-RAG/`** に保存されます
（環境変数 `ZOTERO_RAG_HOME` で変更可）。

| ファイル | 中身 |
|---|---|
| `index.faiss` | 潜在ベクトル本体。4B モデルで 101 文献・8,818 ベクトル（2560 次元）のとき約 90 MB |
| `metadata.json` | ベクトルの行と文献の対応、文献ごとのメタ情報、索引を作ったモデル名 |
| `library.db` | 一節の本文、AI マーカーのキャッシュ、お気に入り、フォルダ、Zotero コレクションの写し、ファクトチェック履歴、追加した PDF の情報 |
| `config.json` | 設定値 |
| `library/` | アプリに直接追加した PDF のコピー |
| `models/` | モデルのキャッシュ（Hugging Face から初回のみダウンロード） |

### 保存タイミング

- **同期中**: 25 文献ごとに `index.faiss` と `metadata.json` を保存します。
  長い初回索引の途中で終了しても、そこまでの分は残ります。
- **同期の最後**: 追加・更新・削除が 1 件以上あれば保存します。変更がなければ書き込みません。
- **PDF の取り込み直後**: その文献を索引して保存します。
- 一節の本文はベクトルより先に `library.db` に書きます。途中で止まった文献は、
  次の同期でもう一度索引されます。

検索、マーカー表示、グラフ表示ではベクトルは書き換えません。

## 5. Zotero との同期とフォルダ

### 同期のタイミング

- アプリの起動時
- サイドバーの「新着を確認」
- 起動中は 5 分ごと（`auto_sync_minutes`。0 で止める）
- コマンドラインの `python app.py --sync`

### 差分の判定

Zotero が各アイテムに持つ `dateModified`（最終更新日時）で判定します
（[indexer.py](../src/indexer.py)）。

| 状態 | 判定 | 処理 |
|---|---|---|
| 新規 | 索引に `key` がない | 埋め込みして追加 |
| 変更あり | `dateModified` が前回と違う | 埋め込み直して置き換え |
| 変更なし | `dateModified` が同じ | 何もしない |
| Zotero から削除 | 現在の一覧に `key` がない | 索引から除く（お気に入りの印は残す） |

**安全装置**: 索引済みの Zotero 文献（10 件以上）の半分超が一覧から消えている場合、
データフォルダの指定違いとみなして同期を中止し、索引を消しません。

### フォルダ

| 種類 | 内容 | 編集 |
|---|---|---|
| Zotero コレクション | 入れ子も含めて同期のたびに写す。親を選ぶとサブコレクションの文献も表示 | Zotero 側のみ（アプリでは読み取り専用） |
| マイフォルダ | アプリ内だけのフォルダ。1 つの文献を複数のフォルダに入れられる | アプリで作成・名前変更・削除 |

Zotero 側には何も書き込みません（[folders.py](../src/folders.py),
[ui/folder_panel.py](../src/ui/folder_panel.py)）。

## 6. 埋め込みモデル

対応モデルは [embedding_models.py](../src/embedding_models.py) に登録されています。
いずれも無料で、Hugging Face Hub からのみ取得し、ダウンロード後はオフラインで動きます。

| モデル | 次元 | ダウンロード | 既定のしきい値 | 位置づけ |
|---|---|---|---|---|
| `Qwen/Qwen3-Embedding-4B` | 2560 | 約 8 GB | 0.45 | 高精度（既定）。メモリ 16 GB 以上を推奨 |
| `Qwen/Qwen3-Embedding-0.6B` | 1024 | 約 1.2 GB | 0.45 | 軽量 |
| `intfloat/multilingual-e5-large` | 1024 | 約 2.1 GB | 0.78 | 従来の既定 |

### 初回起動時の選択

初めて GUI を起動すると、メインウィンドウの前に 4B と 0.6B のどちらを使うかを
選ぶダイアログが出ます（[ui/model_choice.py](../src/ui/model_choice.py)）。

- メモリが 16 GB 以上なら 4B、未満なら 0.6B が選択済みで表示されます。
- 「終了」で閉じると何もダウンロードせず、次回の起動でもう一度聞きます。
- すでに索引がある環境では聞きません。設定ファイルが失われていても、索引を
  作ったモデルをそのまま使います。
- `--sync` などコマンドラインだけで使い始めた場合は 4B になります。

### モデルの変更

設定画面で変更すると、**アプリの再起動後**に新しいモデルへ切り替わります。
索引は作成時のモデル名を記録しているので、次の同期で全文献を埋め込み直し、
しきい値も新しいモデルの既定値に戻ります（類似度の目盛りがモデルごとに違うため）。

実測（101 文献・8,818 一節、この Mac）:

| モデル | 全文献の索引にかかる時間 |
|---|---|
| Qwen3-Embedding-4B | 約 1 時間 |
| Qwen3-Embedding-0.6B | 約 12 分（モデルのダウンロードを含む） |

### モデルごとの入力形式

アプリが自動で付けます。

- Qwen3: 質問文の前に検索用の指示文を付け、一節はそのまま。GPU では float16 で読み込みます。
- E5: 質問は `query: `、一節は `passage: ` を前に付けます。

登録のないモデルも、`config.json` の `embedding_model` と `embedding_dim` を
書けば接頭辞なしで使えます。**索引時と検索時は必ず同じモデル**です。

## 7. 意味検索とベクトル索引

- ベクトルは L2 正規化して FAISS の内積インデックスに入れます。正規化済みの
  内積はコサイン類似度と一致します。
- 意味検索の画面は**一節単位**で結果を出します。クリックすると文献ビューアの
  その一節へ移動します。
- しきい値（`similarity_threshold`）未満の結果は表示しません。
- インデックスの形式は規模で切り替わります。
  - 50,000 ベクトル未満: `IndexFlatIP`（全探索・厳密）
  - 50,000 ベクトル以上: `IndexIVFFlat` に自動で作り直します
    （`nlist = max(16, √N)`, `nprobe = min(nlist, 16)`）。

現在の環境は 8,818 ベクトルなので、全探索（厳密）で動いています。

しきい値 0.45 の根拠（実測。無関係な質問の最上位と、関連する質問の最上位の比較）:

| モデル | 無関係な質問の最大 | 関連する質問の最小 |
|---|---|---|
| Qwen3-Embedding-4B | 0.359 | 0.585 |
| Qwen3-Embedding-0.6B | 0.394 | 0.475 |

## 8. 文献ビューアとマーカー

### マーカーの種類（[highlights.py](../src/highlights.py)）

| マーカー | 色 | 選び方 |
|---|---|---|
| AI 重要文 | 緑 | 文献の重心ベクトル（タイトルと要旨があれば混ぜる）に近い一節を選び、その中で最も近い 1 文に印を付ける。既定 5 文（`key_sentences`）。結果は `library.db` にキャッシュ |
| 探したい文 | 黄 | 入力した文に意味が近い、その文献の一節 |
| 開いた一節 | 薄い青 | 意味検索の結果などから開いた箇所 |

生成モデルは使わず、抜き出しだけで動きます。

### テキスト表示と PDF 表示

要旨の下の「テキスト / PDF」ボタンで切り替えます。選んだ表示は `document_view`
に保存されます。

- **テキスト**: 抽出した本文を一節ごとに表示します。
- **PDF**: 元の PDF のページに同じマーカーを重ねて表示します
  （[ui/pdf_view.py](../src/ui/pdf_view.py)。PyQt6 に同梱の QtPdf を使用）。
  ページは表示幅に合わせ、見えている付近だけを描画します。

PDF 上の位置は、マーカーの文を PDF のテキスト層から探して決めます
（[pdf_locate.py](../src/pdf_locate.py)）。抽出テキストと PDF では改行、ハイフン、
合字、空白が違うため、両方を「文字だけ」に正規化して比べ、途中が違う文は
先頭と末尾で探します。実測では 100 文献・782 文のうち 780 文（99.7%）を特定できました。

制限:

- テキスト層のないスキャン PDF は、マーカーなしで表示されます。
- 位置を特定できなかったマーカーは件数を表示します（テキスト表示では見られます）。
- 拡大縮小はありません。細かく読むときは「PDF を開く」で外部のビューアを使います。

## 9. 引用ファクトチェック

原稿を貼り付けると、`(著者, 年)` と `著者 (年)` の形の引用ごとに判定します
（[factcheck.py](../src/factcheck.py)）。

1. 著者の姓と年で、ライブラリから引用先の文献を探す。
2. その文献から、主張に意味が近い一節を取り出す（既定 4 件、`factcheck_candidates`）。
3. ローカルの NLI モデル（[nli.py](../src/nli.py)）で、一節が主張を含意するか矛盾するかを判定する。
4. 判定と根拠の一文を返す。

| 判定 | 条件 |
|---|---|
| 支持 | どれかの一節が主張を含意し、候補全体としては矛盾していない |
| 矛盾 | 候補の矛盾スコアの**中央値**がしきい値以上で、含意する一節がない |
| 一部支持 | 上のどちらでもない（信号が食い違う場合を含む） |
| 文献なし | 著者と年に合う文献がライブラリにない |

1 つの NLI スコアは無関係な一節にも高く出ることがあるため、候補をまとめて見ます。
しきい値は `entail_threshold` と `contradict_threshold`（どちらも 0.5）です。

- NLI モデル: `MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7`
  （約 560 MB。「チェックする」を初めて押したときにダウンロード。既定では CPU で実行）
- 履歴は `library.db` に保存され、ダッシュボードに表示されます。
- 判定は機械的な目安です。最終確認は根拠の一文と原文で行ってください。

## 10. 関連グラフ

2 種類の線で文献どうしの関係を表します（[graph.py](../src/graph.py)）。

| 線 | 意味 | 求め方 |
|---|---|---|
| 引用（実線の矢印） | A が B を引用 | B のタイトル（25 文字以上）が A の本文に現れる。Zotero は引用関係を持たないため本文から検出 |
| 類似（破線） | 内容が近い | 文献ごとの平均ベクトルのコサインで、互いに近傍 k 件（既定 3、`graph_neighbors`）に入っている |

配置は、反発・ばね・中心への引力による力学モデルです。

## 11. セキュリティ設計

- **Zotero は読み取り専用**: `zotero.sqlite` は一時ファイルにコピーしてから読みます。
  Zotero 本体の DB をロックも変更もしません。
- **ローカル完結**: 文献や原稿は外部に送信しません。外向きの通信は、モデルの
  初回ダウンロード（Hugging Face）だけです。キャッシュ済みの埋め込みモデルは
  ネットワークに触れずに読み込みます。
- **秘密情報を持たない**: Zotero ローカル API は認証不要で、保存する秘密情報はありません。
- **入力はデータとして扱う**: 質問文や原稿はベクトルに変換するだけで、実行しません。
  SQL はすべてパラメータ化クエリです。
- **依存の隔離**: 専用の仮想環境（`venv`）で動作します。

```

requirements.txt       依存ライブラリ（バージョン固定）

  config.py            設定とパス
```

## 14. インストールと起動

### クローン直後

リポジトリにはソースコードとドキュメントだけが入っています。`venv/`、
`Zotero-RAG.app`、モデル、潜在ベクトルは含まれないので、次の手順で用意します。

**前提:** Python 3.10 以上、Zotero（文献が登録済み）。`.app` のビルドは macOS 用です。

```bash
# 1. リポジトリを取得
git clone git@github.com:<ユーザー名>/Zotero-RAG.git
cd Zotero-RAG

# 2. 仮想環境を作成して依存をインストール
python3 -m venv venv
venv/bin/pip install --upgrade pip
venv/bin/pip install -r requirements.txt

# 3.（macOS）アイコンを生成し、ダブルクリックで起動できる .app をビルド
venv/bin/python scripts/make_icon.py
bash scripts/build_app.sh

# 4. 起動
open Zotero-RAG.app          # または: venv/bin/python app.py
```

Windows / Linux では手順 3 は不要です。`venv/bin/python app.py`
（Windows は `venv\Scripts\python app.py`）で起動します。

初回起動では、Embedding モデルを選ぶ → モデルをダウンロード → ライブラリ全体を
索引、の順に進みます。2 回目以降は新着分だけを同期します。

### Zotero ローカル API を使う場合（任意）

アプリは Zotero が閉じていても DB を読み取って動きます。ローカル API を使う場合は、
Zotero を起動し **設定 → 詳細 →「この PC 上の他のアプリケーションとの通信を許可する」**
を有効にしてください。自動で API 経由に切り替わります。

## 15. 操作方法

### GUI

1. `Zotero-RAG.app` を起動する。初回だけ Embedding モデルを選ぶ。
2. 起動時に新着を確認する（サイドバーに進捗を表示）。以後は 5 分ごと。
3. **ライブラリ**: 左のフォルダで絞り込む。文献カードの右クリックでマイフォルダに出し入れ。
   「＋ 文献を追加」またはドラッグ&ドロップで PDF を追加。
4. **文献ビューア**: 「テキスト / PDF」で表示を切り替える。重要文をクリックするとその位置へ移動。
   「探したい文」に文を入れると、近い箇所に黄色のマーカーが付く。
5. **意味検索**: 質問を入力（日本語でも英語でも可）。結果の一節をクリックで原文へ。
6. **引用ファクトチェック**: 原稿を貼り付けて「チェックする」。
7. **関連グラフ**: 引用と類似の関係を見る。
8. **設定**: しきい値、表示件数、Embedding モデルを変更する。

### コマンドライン

```bash
venv/bin/python app.py --status                # 連携状況と索引の状態
venv/bin/python app.py --sync                  # 索引を構築 / 更新
venv/bin/python app.py --search "視覚野の階層的表現"
venv/bin/python app.py --factcheck draft.txt   # 原稿ファイルの引用を照合
```

### テスト

```bash
venv/bin/python -m pytest tests -q
```

## 16. 困ったときは

| 症状 | 原因と対処 |
|---|---|
| Zotero に接続できない | データフォルダが見つからない。設定画面の Zotero データフォルダ、または環境変数 `ZOTERO_DATA_DIR` を確認 |
| 「同期に失敗: … indexed papers are missing from Zotero」 | 別のライブラリやフォルダを指している可能性。設定画面のデータフォルダを確認（索引は消えていません） |
| 検索結果が 0 件 | しきい値が高い可能性。設定画面の最小類似度を下げる（0.6B は 4B より低めに出ます） |
| 初回の起動が長い | モデルのダウンロードと全文献の索引中。4B は 100 文献で約 1 時間、0.6B は約 10 分 |
| メモリが足りない / 動作が重い | 設定画面で Qwen3-Embedding-0.6B に変更して再起動 |
| モデルを変えたい | 設定画面の「Embedding モデル」で選んで保存し、再起動（全文献を再索引） |
| PDF 表示でマーカーが出ない | スキャン PDF（テキスト層なし）の可能性。テキスト表示では確認できます |
| 初回のモデル選択の画面を確認したい | 空のフォルダを `ZOTERO_RAG_HOME` に指定して起動 |
| 索引を作り直したい | アプリを終了し、`index.faiss` と `metadata.json` を削除して `--sync` |
