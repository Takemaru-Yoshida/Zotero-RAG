## 1. このアプリは何をするか

キーワードの完全一致ではなく、**文章の「意味」**で Zotero ライブラリの論文を
検索します。たとえば「対照学習の自己教師あり手法」と入力すると、その語が
本文に出てこなくても内容が近い論文を見つけられます。日本語で入力して英語論文を
探す、といった**言語をまたいだ検索**もできます。

仕組みの核心は次の2つです。

- **潜在ベクトル化（埋め込み）**: 各論文の本文を埋め込みモデルに通し、
  1024 次元の数値ベクトルに変換します。意味が近い文章はベクトルも近くなります。
- **コサイン類似度検索**: 問い合わせ文も同じモデルでベクトル化し、保存済みの
  論文ベクトルとの類似度を計算して、近い順に表示します。

**バックグラウンドスレッド**（`QThread`）で実行するため、画面が固まりません。

## 3. 処理フロー（7ステップ）

仕様の番号と実装の対応は次の通りです。**ステップ1〜4は初回（と新着検知時）**、
**ステップ5〜7は毎回の検索**で動きます。

| ステップ | 内容 | 実装箇所 |
|---|---|---|
| 1 | Zotero と連携（ローカルAPI／DB読み取り） | `zotero_client.py` |
| 2 | 論文を抽出（journalArticle, preprint など） | `ZoteroClient.fetch_papers()` |
| 3 | 各論文の本文を埋め込みモデルで潜在ベクトル化 | `embedder.py` |
| 4 | 潜在ベクトルをディスクに保存 | `vector_store.py` |
| 5 | 問い合わせ文を**同じモデル**でベクトル化 | `Embedder.embed_query()` |
| 6 | 保存済みベクトルとのコサイン類似度を計算 | `VectorStore.search()` |
| 7 | 類似度が高い順に表示（top-K＋閾値） | `gui.py` |

### ステップ3の詳細：長い本文の「チャンク化」

論文は数千〜数万トークンと長く、モデルの一度の入力上限（512トークン）を
超えます。そこで本文を **512トークンずつ・64トークン重ねながら** 複数の窓
（チャンク）に分割し、**チャンクごとに**ベクトル化します
([embedder.py](../src/embedder.py))。これにより「論文のどこか一部分」が
問い合わせに合致した場合でもヒットできます。

論文1件＝複数ベクトル。論文のスコアは「その論文の各チャンク類似度の最大値」を
採用します（`score_aggregation = "max"`）。

### E5 モデル固有の接頭辞

採用モデル（multilingual-e5-large）は、入力に役割を示す接頭辞を付ける前提で
学習されています。アプリが自動付与します。

- 索引する本文 → `passage: ...`
- 検索の問い合わせ → `query: ...`

## 4. 潜在ベクトルの保存先と保存タイミング

### 保存先

すべて **`~/Library/Application Support/Zotero-RAG/`** に保存されます。

| ファイル | 中身 |
|---|---|
| **`index.faiss`** | **潜在ベクトル本体**。全チャンクの 1024 次元ベクトルを格納した FAISS インデックス（規模に応じて Flat または IVF）。約 19 MB（4,872 ベクトル時） |
| `metadata.json` | ベクトル行→論文の対応表（`row_meta`）と、論文ごとのメタ情報（`papers`：タイトル・著者・年・種別・要約・`dateModified`・チャンク数） |
| `config.json` | 設定値（モデル名・top_k・閾値・対象アイテム種別 など） |
| `models/` | 埋め込みモデルのキャッシュ（HuggingFace からの初回 DL 分、約 2 GB） |

> ベクトルの数値そのものは `index.faiss`（バイナリ）に入っています。
> `metadata.json` は「`index.faiss` の N 行目はどの論文のどのチャンクか」を
> ひも付ける索引で、人間が読める JSON です。

保存場所は環境変数 `ZOTERO_RAG_HOME` で変更できます。

### 保存タイミング

潜在ベクトルがディスクに書き込まれるのは、**`Indexer.sync()` の中で、
追加・更新・削除が1件以上あったときだけ**です。詳細な流れ:

1. **埋め込み中はメモリ上のみ** — 新規／変更された論文を1件ずつエンコードし、
   `VectorStore.add_paper()` でメモリ上の FAISS インデックスに追加します。
   この段階ではまだディスクに書きません。
2. **`sync()` の最後に一括永続化** — 追加/更新/削除が1件でもあれば、
   `VectorStore.optimize()`（必要なら IVF 化）→ `VectorStore.save()` を呼び、
   `index.faiss` と `metadata.json` を**まとめて上書き保存**します。
3. **変更ゼロなら保存しない** — 全件の `dateModified` が前回と同じなら、
   何も書き込まずに終了します（高速）。

`sync()`（＝保存の起点）が呼ばれる瞬間は次の3つです。

- **アプリ起動時**（`MainWindow` が自動で `start_sync()` を実行）
- **「Check for new papers」ボタンを押したとき**
- **コマンドラインで `python app.py --sync` を実行したとき**

**検索（ステップ5〜7）ではベクトルは保存しません**（読み取り専用）。
検索時に top-K や閾値を変えた場合は `config.json` のみ更新されますが、
これは設定であってベクトルではありません。

```
[起動 / 同期ボタン / --sync]
        │
        ▼
  sync() 開始
        │ Zoteroから現在の論文一覧を取得
        ▼
  差分判定（dateModified 比較）
        │   新規・変更あり ──► 1件ずつエンコード ──► メモリ上のFAISSへ add
        │   削除あり ─────────► メモリ上のFAISSから remove
        ▼
  追加/更新/削除が1件以上？
        ├─ はい ─► optimize()（必要ならIVF化）─► save() で index.faiss + metadata.json を保存 ★ここで保存
        └─ いいえ ─► 何も保存せず終了
```

## 5. 増分同期（新着論文の検知）の仕組み

Zotero の論文は増減します。アプリは**起動時・検索時・同期ボタン押下時**に
最新の一覧を取得し、前回保存した内容と突き合わせて、**必要な分だけ**処理します
（[indexer.py](../src/indexer.py)）。

判定は Zotero が各アイテムに持つ **`dateModified`（最終更新日時）** を使います。

| 状態 | 判定 | 処理 |
|---|---|---|
| 新規論文 | インデックスに `key` が無い | 埋め込みして追加 |
| 変更あり | `dateModified` が前回と違う | 再埋め込みして置換 |
| 変更なし | `dateModified` が同じ | スキップ（再計算しない） |
| Zotero から削除 | 現一覧に `key` が無い | インデックスから除去 |

変更のない論文はスキップするため、大規模ライブラリでも再同期は高速です
（実測：101件すべて変更なしの再同期で約 1.6 秒）。

## 6. 埋め込みモデルの選定理由

採用モデル: **`intfloat/multilingual-e5-large`**（HuggingFace Hub からのみ取得）

- **無料・軽量**: 約 1.1 GB。初回ダウンロード後は**完全オフライン**で動作。
- **多言語（英語・日本語）**: 多言語検索ベンチ（MTEB / JMTEB）で英日とも高スコア。
- **実行環境**: Apple GPU（MPS）／CUDA／CPU を自動判定。
- **入手元の制限順守**: モデルは HuggingFace のみから取得します。

別モデル（例: `BAAI/bge-m3`）に変えたい場合は、`config.json` の
`embedding_model` と `embedding_dim` を書き換えて再同期してください。
**索引時と検索時は必ず同じモデル**にする必要があります（ベクトル空間が
一致しないと類似度が無意味になるため）。

## 7. ベクトル検索の効率化（FAISS / IVF）

- ベクトルは **L2 正規化** してから、FAISS の**内積インデックス**に格納します。
  正規化済みベクトルの内積は**コサイン類似度**と一致するため、これだけで
  コサイン検索になります。
- 規模に応じてインデックス形式を自動で切り替えます。
  - 小規模（チャンク数 < 4000）: `IndexFlatIP`（全探索・厳密）
  - 大規模（チャンク数 ≥ 4000）: **`IndexIVFFlat`（IVF：転置ファイル型 ANN）**
    に自動再構築。`nlist ≈ √N` のクラスタに分割し、`nprobe` 個だけ探索する
    ことで、わずかな再現率の低下と引き換えに大幅な高速化を実現します。
- 検索時は top-K より多めにチャンクを取り出し、同じ論文に属するチャンクを
  集約して論文単位のスコアに変換します（[vector_store.py](../src/vector_store.py)）。

あなたの環境では 4,872 ベクトルのため、**自動的に IVF（nlist=69）** に
最適化されています。

## 8. セキュリティ設計

- **Zotero へは読み取り専用**: ライブラリ DB（`zotero.sqlite`）は直接開かず、
  **一時ファイルにコピーしてから読み取ります**。Zotero 本体の DB を
  ロック・破損させることはありません。書き込みは一切しません。
- **ローカル完結**: データは外部に送信されません。外向き通信は
  **初回のモデルダウンロード（HuggingFace）だけ**です。
- **秘密情報を持たない**: Zotero ローカル API は認証不要で、保存する
  秘密情報はありません。
- **入力はデータとして扱う**: 問い合わせ文は埋め込みベクトルに変換するだけで、
  コードとして実行しません。DB アクセスはすべて**プレースホルダ付きの
  パラメータ化クエリ**で、SQL インジェクションを防ぎます。
- **依存の隔離**: 専用の仮想環境（`venv`）上で動作し、システム環境を汚しません。
- **モデル入手元の限定**: モデルは HuggingFace / PyTorch のみから取得します。

## 9. モジュール構成（ファイルの役割）

```
app.py                 エントリーポイント（GUI / --sync / --search / --status）

src/
  config.py            設定とパス管理（Config データクラス）
  zotero_client.py     Zotero連携：ローカルAPI＋読み取り専用SQLiteフォールバック
  embedder.py          埋め込みモデル：e5-large・チャンク化・接頭辞付与
  vector_store.py      FAISSインデックス（Flat→IVF）・保存/読込・検索
  indexer.py           ステップ2〜4＋増分同期の制御
  search.py            ステップ5〜7（問い合わせ→類似度→整形）
  gui.py               PyQt6 のデスクトップ画面
scripts/
  make_icon.py         icon.svg → icon.icns 生成
  build_app.sh         ダブルクリック起動できる .app を生成
assets/                icon.svg / icon.png / icon.icns
docs/                  ドキュメント一式（本書・README・スライド）
```

| クラス | 役割 |
|---|---|
| `Config` | 設定値の読み書きと、保存パス（index/metadata/model）の算出 |
| `ZoteroClient` | API が使えれば API、だめなら SQLite と全文キャッシュを使う司令塔 |
| `Paper` | 論文1件の正規化データ（タイトル・著者・本文・`dateModified` 等） |
| `Embedder` | モデルの遅延ロード、チャンク化、`passage:`/`query:` 付与、ベクトル化 |
| `VectorStore` | ベクトルの追加/削除/保存/読込、IVF最適化、類似度検索 |
| `Indexer` | Zotero取得→差分判定→必要分だけ埋め込み→保存 を統括 |
| `SearchEngine` | 問い合わせをベクトル化し、閾値・top-Kで結果を返す |
| `MainWindow` | 画面構築とバックグラウンド処理（`SyncWorker`/`SearchWorker`）の連携 |

## 10. 設定ファイルの項目

`~/Library/Application Support/Zotero-RAG/config.json`（初回起動時に自動生成）。
主な項目:

| 項目 | 既定値 | 意味 |
|---|---|---|
| `zotero_data_dir` | `~/Zotero` | Zotero データフォルダの場所 |
| `zotero_api_base` | `http://127.0.0.1:23119` | ローカル API の宛先 |
| `embedding_model` | `intfloat/multilingual-e5-large` | 埋め込みモデル名 |
| `embedding_dim` | `1024` | ベクトル次元（モデルに合わせる） |
| `max_seq_length` | `512` | 1チャンクの最大トークン数 |
| `chunk_overlap_tokens` | `64` | チャンク間の重なり |
| `device` | `auto` | `auto`/`cpu`/`cuda`/`mps` |
| `top_k` | `10` | 表示する最大件数 |
| `similarity_threshold` | `0.78` | この値未満のコサイン類似度は非表示 |
| `score_aggregation` | `max` | 論文スコアの集約方法（`max`/`mean`） |
| `item_types` | journalArticle ほか | 索引対象のアイテム種別 |

> top_k と閾値は GUI 上でも変更でき、検索時に `config.json` へ保存されます。

## 11. インストールと起動

### 11.1 Git からクローン／ダウンロードした場合の立ち上げ方

リポジトリには**ソースコードとドキュメントのみ**が含まれ、次のものは
`.gitignore` で除外されています。クローン直後は存在しないため、再生成します。

- `venv/`（仮想環境）… `python3 -m venv` で再生成
- `Zotero-RAG.app`（起動用バンドル）… `build_app.sh` で再生成
- `assets/icon.icns` 等のアイコン中間物 … `make_icon.py` で再生成
- `models/`（モデル）… 初回起動時に HuggingFace から自動ダウンロード
- `index.faiss` / `metadata.json`（**潜在ベクトル**）… 初回同期時に各自の環境で構築

> 潜在ベクトルは人それぞれ異なるため共有されません。クローンした人の
> Zotero ライブラリに対して、初回起動時に**その人専用のベクトル**が
> `~/Library/Application Support/Zotero-RAG/` に作られます。

**前提条件:** Python 3.10 以上、Zotero（インストール済みで論文が登録済み）。
アイコン生成と `.app` ビルドは macOS 用の手順です。

```bash
# 1. リポジトリを取得
git clone git@github.com:<ユーザー名>/Zotero-RAG.git
cd Zotero-RAG

# 2. 仮想環境を作成して依存をインストール
python3 -m venv venv
venv/bin/pip install --upgrade pip
venv/bin/pip install -r requirements.txt

# 3.（macOS）アイコンを生成し、ダブルクリック起動できる .app をビルド
venv/bin/python scripts/make_icon.py
bash scripts/build_app.sh

# 4. 起動
open Zotero-RAG.app          # GUI。または: venv/bin/python app.py
```

**macOS 以外（Windows / Linux）の場合:** 手順 3 の `.app` ビルドは不要です。
手順 2 のあと、次のコマンドで GUI を起動できます。

```bash
venv/bin/python app.py          # macOS / Linux
venv\Scripts\python app.py      # Windows
```

初回起動時にモデル（約 1.1 GB）を HuggingFace からダウンロードし、ライブラリ
全体のインデックスを構築します。2回目以降は新着分のみ同期するため高速です。

### 11.2 既にセットアップ済みの環境で起動する場合

```bash
cd ~/Zotero-RAG
open Zotero-RAG.app                            # GUI を起動
# または
venv/bin/python app.py                         # GUI を起動
```

### Zotero ローカル API を使う場合（任意）

アプリは Zotero が閉じていても DB を読み取って動きますが、公式の
ローカル API を使いたい場合は、Zotero を起動し
**設定 → 詳細 →「この PC 上の他のアプリケーションとの通信を許可する」**
を有効にしてください。アプリが自動的に API 経由に切り替わります
（全文は Zotero のキャッシュから取得するため、結果は同じです）。

## 12. 操作方法（GUI / コマンドライン）

### GUI

1. `Zotero-RAG.app` をダブルクリックで起動。
2. 起動時に自動で新着論文を確認（進捗バーとステータスに表示）。
3. 検索ボックスに調べたい内容を入力（英語でも日本語でも可）して **Search**。
4. **Results**（最大表示件数）と **Min similarity**（最低類似度）をその場で調整可能。
5. 結果カードの **Open in Zotero** で、その論文を Zotero アプリ内で直接開く。
6. **Check for new papers** でいつでも手動同期。

### コマンドライン


## 13. 困ったときは（トラブルシュート）

| 症状 | 原因と対処 |
|---|---|
| 「Cannot reach Zotero」 | Zotero データフォルダが見つからない。`config.json` の `zotero_data_dir` を確認、または環境変数 `ZOTERO_DATA_DIR` を設定。 |
| 検索結果が0件 | 閾値が高すぎる可能性。GUI の **Min similarity** を下げる（例 0.78→0.70）。 |
| 検索が「No papers indexed」 | 先に **Check for new papers**（または `--sync`）を実行。 |
| 起動が遅い（初回） | モデルのダウンロード中。完了後の2回目以降は高速。 |
| モデルを変えたい | `config.json` の `embedding_model`/`embedding_dim` を変更し、`--sync` で作り直す。 |
| インデックスを作り直したい | `~/Library/Application Support/Zotero-RAG/` の `index.faiss` と `metadata.json` を削除して `--sync`。 |
